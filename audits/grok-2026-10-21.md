## Threat model (STRIDE)

Spoofing: Cloudflare Access is the admin door. `getAdminSession` fails closed when `ADMIN_EMAIL`, the team domain, or the audience is missing, and the localhost bypass requires the exact string `ACCESS_DEV_BYPASS === "1"`. Carrel is a separate door: one site key, 32 characters or more, compared as SHA-256 digests.

Tampering: post bodies and Carrel article bodies are sanitized on save. Page content blocks are not (GE-3). A push to `main` deploys, and this private repo cannot turn on branch protection (GE-1).

Repudiation: Carrel writes a change id to the log and a snapshot before an edit. Admin saves snapshot on every intent except autosave. Nightly backups write `_complete.json` only after the checks.

Information disclosure: preview links are unauthenticated and fail open to a literal in source when the signing secret is unset (GE-2). `/health` returns backup age and no table names. Sentry events include the full URL (GE-10). Resource ids in `wrangler.jsonc` are omitted here.

Denial of service: `/admin` and `/admin/ai` have a KV window. Scores have their own. `POST /subscribe` does not (GE-6). Carrel uses the rate-limit binding and fails closed if that call throws.

Elevation: the admin middleware throws 403 before `next()` when there is no session. Carrel refuses a missing, short, or wrong key before any route runs, and it will not take a slug that already belongs to an episode.

## Findings

### GE-1 MAJOR, CI and deploy, high confidence

`CLAUDE.md` line 20 and `README.md` say Cloudflare Workers Builds deploys on every push to `main`, and a merge to `main` is a production deploy. `.github/workflows/ci.yml` lines 1 to 2 say the same, and that CI "should pass before that." The workflow cannot make that true. It runs on `push` to `main` and on `pull_request`, in parallel with the deploy, with `contents: read`. `verify` and `audit` do not gate each other, and neither gates Workers Builds.

Branch protection and rulesets both return HTTP 403 because this private repo is on a plan that does not offer them. `devkit/default.json`, which `renovate.json` extends, says the same thing in its own words, and it automerges non-major updates, including minor and patch of Dustin's own packages, once CI on the pull request is green. That merge is a production deploy. A direct push to `main` is a production deploy with no CI wait at all.

The Cloudflare API was not available from this session, so the dashboard job was not queried. The finding rests on the repo's own deploy statement plus the GitHub 403s.

What goes wrong: a bad commit, or a Renovate minor of `site-runtime`, `site-api`, `d1-dump`, or `wrangler`, reaches production even when the post-merge `verify` job would have failed. `npm run deploy` is `build` then `wrangler deploy`. It does not run migrations. The worker still ships.

Smallest fix: point Workers Builds at a workflow job that `needs` the verify job, or turn the automatic production deploy off and deploy from that job by hand. Required reviews need a plan that can hold a ruleset.

### GE-2 MAJOR, security, high confidence on the code

`app/lib/preview.server.ts` lines 5 to 9. `tokenFor` uses `env.BETTER_AUTH_SECRET` or the literal `germomics-preview-secret`. The token is the first 32 hex characters of SHA-256 of `secret:preview:<id>`. `app/routes/preview.$id.$token.tsx` lines 17 to 24 accept that token and then load the post by id with no status filter, so a draft is rendered.

`BETTER_AUTH_SECRET` is optional in `app/worker-secrets.d.ts`. Access fails closed when its configuration is missing. Preview fails open, and the fallback is in the repository, so the construction is public. Post ids are integers.

Live GET of `/preview/1` through `/preview/5` with the fallback token returned 404. A wrong token and a missing row both return 404, so that probe does not show whether production has the secret set. If the secret is unset, every existing draft is readable. The 2026-10-09 note in `research/cloudflare-audit.md` already asked for this to be removed.

Smallest fix: if `BETTER_AUTH_SECRET` is missing, `verifyPreviewToken` returns false. Sign with HMAC. Keep the tests that a token for another post fails, and add one where the secret is empty.

### GE-3 MAJOR, security, high confidence

`app/routes/admin.content.$key.tsx` lines 29 to 38 store `value` as submitted. The field hint on line 64 says the body is "Rendered as sanitized HTML." `upsertBlock` in `app/lib/content.server.ts` lines 139 to 150 writes that string. `BodyRenderer` (`app/components/content/BodyRenderer.tsx` lines 33 to 37) injects it with `dangerouslySetInnerHTML`. About, privacy, terms, contact, and `/txasm` all render page blocks that way.

Post saves and Carrel writes call `sanitizeHtml`. Page saves do not. The content-security policy is report-only (GE-4), so a `script` element or an `on*` handler in a published page runs for visitors. The only writer is the signed-in admin. A paste into that textarea is a normal edit.

`contact.tsx` lines 27 to 29 and `privacy.tsx` lines 27 to 29 also replace `{{email}}` and `{{address_line}}` with `show.ownerEmail` and the address setting, with no escape, and that replacement happens at render.

Smallest fix: run `sanitizeHtml` on page values inside `upsertBlock` (or the action), and escape the two substituted strings before they are concatenated. Add a test that a `script` in `page:about` is absent from the public HTML.

### GE-4 MINOR, security, high confidence

`app/lib/security.server.ts` lines 25 to 42 and 71 to 75 set `Content-Security-Policy-Report-Only`. `script-src` and `style-src` include `'unsafe-inline'`. Live responses on `/` and `/health` send that report-only policy, plus HSTS for one year with `includeSubDomains`, `nosniff`, `X-Frame-Options: DENY`, a Permissions-Policy, and `tdm-reservation`.

The post sanitizer is the real control for episode and article bodies, and the plant showed the suite notices when `script` is no longer dropped. Report-only adds no blocking. It is the right order only while the violations are being read. The file still describes it as waiting for that review. GE-3 is the path that does not have the sanitizer in front of the same sink.

Smallest fix: after GE-3, enforce the policy that the report-only header is already spelling, and drop `'unsafe-inline'` from `script-src` when the inline theme script can move.

### GE-5 MINOR, security, high confidence

`app/lib/sanitize.server.ts` lines 27 to 28 allow `srcset` and `sizes` on `img` and `source`. `safeUrl` runs only for `href` and `src` (lines 86 to 88). The header comment says `javascript:`, `vbscript:`, and `data:` URLs are stripped. A scratch test fed an image whose `srcset` was `javascript:alert(1)` and a `data:` URL. Both survived. The 12 committed tests stayed green.

An `img` does not run a `javascript:` URL as script in current browsers. The hole is still a broken statement of the policy, and `srcset` is how the figure scripts build responsive images.

Smallest fix: split `srcset` on commas, run `safeUrl` on the URL token of each candidate, and drop the candidate when it fails. Keep the scratch assertion.

### GE-6 MINOR, abuse, high confidence

`app/routes/subscribe.tsx` lines 27 to 51. `POST /subscribe` stores an email, a consent time, and `crypto.randomUUID()` as the unsubscribe token. The address is checked with a regex and a 254 character cap. Consent must be the string `on`. There is no rate limit, captcha, or proof of control of the mailbox. `enforceRateLimit` only matches `/admin` and `/admin/ai` (`security.server.ts` lines 95 to 98). Scores are limited to 5 per minute per IP and the suite checks that. Re-subscribing keeps the old token on purpose (`public-writes.test.ts`).

What goes wrong: a client can fill `subscribers` with addresses that never consented in any real sense beyond a forged form post. The row is personal data.

Smallest fix: the same KV window scores already use, on `POST /subscribe`, keyed by `CF-Connecting-IP`, with a small per-window cap.
